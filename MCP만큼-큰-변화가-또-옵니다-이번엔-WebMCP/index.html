WebMCP — 웹사이트가 AI에게 조작 도구를 내주는 방법

AI가 화면을 분석하지 않고 사이트가 준비한 도구를 쓰는 원리를 짚어요

코드깎는노인· 07:26· 유튜브 영상 정리
원본 영상 보러 가기 →

핵심만 먼저

  1. WebMCP는 웹사이트가 AI 에이전트용 조작 도구를 코드로 미리 등록해 두는 브라우저 기능이에요.
  2. 지금은 AI가 사람용 화면을 매번 분석해 조작 코드를 짜야 해서, 분석이 틀리면 오작동해요.
  3. 사이트는 registerTool로 등록하고, AI는 getTools로 확인한 뒤 executeTool로 실행해요.
  4. AI가 대신 쇼핑·예약하는 시대엔 득이지만, 광고 노출이 수익원인 사이트엔 반갑지 않을 수 있어요.
  5. 아직 실험 단계예요. 크롬 플래그를 켜야 쓸 수 있고, 스펙은 MDN이 아니라 GitHub에서 바뀌고 있어요.

00:00

사람용 웹은 AI에게 불편해요

웹사이트는 버튼, 입력창, 체크박스처럼 눈으로 보고 누르는 요소로 되어 있어요. 영상은 반대 상황을 상상해 봐요. 사이트에 들어갔더니 검은 화면에 명령어를 치라고 나오는 거예요. 이러면 대부분은 창을 닫아 버리겠죠. 그래서 웹은 특별한 지식 없이도 쓸 수 있게 만들어져 왔어요.

AI는 매번 화면을 분석해야 해요

이제 웹을 쓰는 주체에 AI 에이전트도 들어가요. 화면도 결국 코드라서 AI가 못 다루는 건 아니에요. 문제는 AI가 사이트에 올 때마다 페이지 구조를 분석하고, 그에 맞는 조작 코드를 직접 만들어야 한다는 점이에요. 사람용으로 만든 화면을 AI가 자기 편한 도구로 바꿔서 쓰는 셈이죠.

사이트마다 구현 방식과 복잡도가 달라요. 그래서 분석을 잘못하면 엉뚱한 버튼을 누르는 식으로 오작동할 수 있어요.

01:38

WebMCP가 해결하려는 것

WebMCP는 이 문제를 사이트 쪽에서 풀어요. 사람용으로 만든 사이트에 AI도 올 거라고 보고, AI가 쓰기 쉬운 조작 도구를 미리 준비해 두는 거예요. 그러면 AI는 사이트를 분석하거나 도구를 직접 만들 필요가 없어요. 사이트가 코드로 만들어 둔 도구를 그대로 꺼내 쓰면 돼요.

사이트에 득일까요?

영상은 사이트 입장에서 AI를 배려해 주는 게 꼭 좋은지도 짚어요.

사이트 유형WebMCP 지원이이유
상품 판매·예약 서비스득이 될 수 있어요AI가 사용자 대신 찾고 예약하고 구매할 때, AI를 놓치지 않는 창구가 돼요
방문·광고 노출이 수익원인 사이트반갑지 않을 수 있어요사용자가 직접 화면을 보고 눌러야 의미가 있어요

바이브 코딩으로 사이트를 만든다면 코딩 에이전트에게 WebMCP 지원을 붙여 달라고 하면 돼요. 그래도 원리는 알아 두는 게 좋다며 영상은 다음 내용으로 넘어가요.

02:43

웹 API 하나가 더 생긴 것

웹에는 이미지, 오디오, 입력 요소가 있고, 바이너리 코드를 돌리는 WebAssembly와 실시간 양방향 통신을 하는 WebSocket도 있어요. 모두 처음부터 있던 게 아니라 웹이 발전하면서 하나씩 생겼어요. 이런 기능을 웹 API라고 불러요. WebMCP는 이 목록에 하나가 더해진 거예요.

이미지 API에 주소나 크기를 정하는 기능이 있듯이, ModelContext에는 AI용 도구를 등록하고 쓰게 하는 기능이 들어 있어요. 영상의 표현대로 꽤 단출해요.

기능누가 쓰나요하는 일
registerTool사이트AI가 쓸 조작 도구를 등록해요
getToolsAI이 사이트에 등록된 도구와 설명을 확인해요
executeToolAI고른 도구를 실행해요

플래그를 켜야 보여요

ModelContext는 기본으로 꺼져 있어요. 그래서 크롬의 chrome://flags에서 WebMCP for testing 플래그를 켜고 브라우저를 다시 시작해야 해요. 여기서 말하는 브라우저는 사람이 웹 서핑에 쓰는 것이 아니라 AI가 쓰는 브라우저예요. 설정 후 접속하면 콘솔에서 document.modelContext가 잡혀요.

영상에 없는 보충 설명

WebMCP 스펙은 W3C의 Web Machine Learning 커뮤니티 그룹이 내는 초안 보고서예요. 문서 스스로 W3C 표준도 아니고 표준화 트랙에 오른 것도 아니라고 밝히고 있어요. 편집자는 Microsoft와 Google 소속이에요. 플래그 이름에 'for testing'이 붙은 것도 이런 실험 단계라서예요.

04:20

할 일 목록 사이트로 해 보는 데모

데모 사이트는 할 일 목록이에요. 이 사이트에서 AI용 도구라면 목록 조회, 추가, 완료 처리, 삭제 정도가 되겠죠.

사이트 쪽: registerTool로 등록해요

사이트는 각 동작을 하는 코드를 준비해서 registerTool로 등록해요. 도구 하나는 두 부분으로 나뉘어요.

  • 도구 정보: 이름(delete_todo), 사람이 읽을 제목, 설명, 그리고 어떤 입력을 받는지 적은 inputSchema예요.
  • 도구 코드 본체: execute 함수예요. 화면에서 해당 할 일의 삭제 버튼을 찾아 누르고, 성공 여부를 돌려줘요.

코딩 에이전트에게 "WebMCP 지원해 줘"라고 부탁하면, 에이전트가 사이트에 이런 등록 코드를 넣어 주는 거예요.

AI 쪽: getTools로 보고 executeTool로 실행해요

AI는 사이트에 들어오면 먼저 준비된 도구가 있는지 getTools로 확인해요. 도구마다 무슨 용도이고 어떻게 쓰는지 설명이 붙어 있어서, AI는 그걸 읽고 바로 쓸 수 있어요.

할 일 목록을 보고 싶으면 list_todos를 executeTool로 실행해요. 추가, 완료, 삭제도 같은 방식이에요. AI는 화면 구조를 몰라도 사이트가 내준 방법만으로 사이트를 다룰 수 있어요.

페이지가 열리면 자동으로 등록되게

여기까지는 콘솔에서 손으로 등록했어요. 실제로는 코딩 에이전트에게 "접속하면 도구가 미리 등록되어 있게 해 줘"라고 요청해서 사이트를 고치면 돼요. 고친 페이지에 들어가면 도구 네 개가 바로 등록되어 있어요.

영상에 없는 보충 설명

영상에서 쓴 registerTool은 자바스크립트로 도구를 정의하는 명령형(Imperative) 방식이에요. 크롬은 이와 함께 HTML 폼만으로 도구를 정의하는 선언형(Declarative) 방식도 제안하고 있어요. 간단한 입력 폼이라면 자바스크립트 없이 폼 자체를 AI용 도구로 내놓는 방식이에요. 스펙에서 선언형 부분은 아직 비어 있고 별도 설명 문서를 참고하라고 적혀 있어요.

AI 에이전트 쪽 구현과 앞으로의 웹

앞에서 콘솔로 해 본 AI 에이전트 쪽 동작은 프로그램으로도 만들 수 있어요. 영상은 Playwright로 WebMCP를 켠 크롬을 띄우고, 사이트에 접속해 도구를 확인한 뒤 하나씩 실행하는 클라이언트를 보여 줘요.

발표자가 보는 웹의 앞날

발표자는 결국 웹을 쓰는 주체는 AI 에이전트만 남을 수도 있다고 봐요. 그러면 프론트엔드는 필요 없고 백엔드의 API나 MCP만 남겠죠. 하지만 지금 웹이 당장 그렇게 바뀌는 건 불가능에 가까워요.

그래서 발표자는 WebMCP를 현실적인 타협으로 해석해요. 기존 웹은 그대로 쓰고, 프론트엔드 코드에 AI가 조작할 수 있는 인터페이스를 끼워 넣는 방식이라는 거예요.

영상에 없는 보충 설명

스펙 서론도 비슷하게 설명해요. WebMCP를 쓰는 웹 페이지는 도구를 백엔드가 아니라 클라이언트 쪽 스크립트로 구현한 MCP 서버라고 볼 수 있다고 해요. 또 사용자와 에이전트가 같은 화면에서 함께 일하는 흐름을 목표로 한다고 적혀 있어요. 사람용 화면을 없애기보다 나란히 두는 쪽이에요.

출처: WebMCP 스펙 1절 Introduction

스펙은 어디서 보나요

ModelContext API는 웹 API 문서가 보통 올라오는 MDN에서는 찾을 수 없어요. 지금은 Web Machine Learning 그룹의 GitHub 저장소에 스펙이 주로 올라오고, 내용도 활발히 바뀌고 있어요.

영상에 없는 보충 설명

크롬은 WebMCP를 얼리 프리뷰 프로그램으로 공개하고 있어요. 참가 신청을 하면 문서와 데모를 받아 프로토타입을 만들어 볼 수 있어요. 실제 서비스에 넣기 전에 스펙이 바뀌었는지 이 두 곳을 먼저 확인하는 게 좋아요.

이 글에 나온 용어

용어뜻
바이브 코딩코드를 한 줄씩 직접 쓰기보다 AI에게 원하는 걸 말로 설명해서 만들어 가는 개발 방식이에요.
코딩 에이전트코드를 읽고 고치고 명령을 실행하는 일을 스스로 이어서 하는 AI 도구예요. 요청 한 번에 여러 파일을 손봐요.
웹 API브라우저가 웹 페이지에 기본으로 열어 주는 기능 묶음이에요. 이미지 표시, WebSocket 통신처럼 자바스크립트에서 바로 불러 써요.
ModelContextWebMCP가 브라우저에 추가하는 인터페이스 이름이에요. document.modelContext로 접근해서 도구를 등록하고 조회하고 실행해요.
플래그크롬에서 아직 정식 출시 전인 실험 기능을 켜고 끄는 스위치예요. chrome://flags 주소에서 바꿔요.
inputSchema도구가 어떤 입력을 받는지 JSON Schema 형식으로 적은 명세예요. AI는 이걸 보고 올바른 인자를 만들어 넘겨요.
MCPModel Context Protocol의 줄임말이에요. AI 앱이 외부 도구와 데이터에 붙는 방식을 맞춘 공개 규약이라서, 한 번 만든 도구를 여러 AI가 같이 써요.
Playwright브라우저를 코드로 띄우고 조작하는 자동화 도구예요. 테스트나 에이전트가 실제 브라우저를 움직일 때 많이 써요.
