구조도로 보기: GitDiagram

남의 저장소를 처음 열면 폴더가 몇 겹씩 접혀 있어서 어디부터 읽어야 할지 막막해요. 영상이 내놓는 해법은 코드를 읽기 전에 주소창부터 고치는 거예요. 두 꿀팁 모두 GitHub 저장소 주소의 hub 한 단어만 바꿔요.

첫 번째는 hub를 diagram으로 바꾸는 거예요. 영상은 파일이 index.html, script.js, style.css 세 개뿐인 계산기 저장소로 시연해요. 아래 화면에서 주소창이 gitdiagram.com/codewithtoushif/…로 바뀌어 있고, GitDiagram 입력칸에 원래 GitHub 주소가 자동으로 들어가 있어요. 키보드의 엔터 키가 강조돼 있죠.

잠시 기다리면 구조도가 완성돼요. 상자 하나가 파일이나 역할 하나예요. 맨 위의 [index.html]이 진입점이고, 사용자 입력이 [script.js]로 이벤트를 보내요. 스크립트가 클래스를 바꿔 상태를 바꾸면 [style.css]가 그 상태에 맞춰 모양을 입히고, 결과가 맨 아래 'DOM UI surface'에 그려져요. 화살표마다 'triggers events', 'loads', 'creates' 같은 관계 이름이 붙어 있어요.

영상에 없는 보충 설명

제목은 '불법 같은'이라고 하지만 GitHub의 숨은 기능은 아니에요. GitDiagram은 개인 개발자가 만든 오픈소스 서비스이고, README에도 'hub를 diagram으로 바꾸라'는 사용법이 공식으로 적혀 있어요. 구조도는 AI가 저장소를 읽고 만들어요. 상자를 누르면 연결된 파일이나 폴더로 이동하고, 그림을 PNG(Portable Network Graphics)로 내보내거나 Mermaid 원본을 복사할 수도 있어요. 비공개 저장소는 헤더의 Private Repos 메뉴에서 GitHub 토큰을 넣어야 해요.

AI에 넣기 좋게 묶기: Gitingest

두 번째는 저장소를 AI에 통째로 넣고 싶을 때 써요. 이번에는 hub를 ingest로 바꿔요. 아래 화면은 주소창에 gitin까지 친 순간이에요. 뒤쪽 .com/codewithtoushif/…는 그대로 두고 앞부분만 고치고 있어요.

Gitingest 페이지는 세 칸으로 나뉘어요. 왼쪽 위 Summary에는 저장소 이름과 분석한 파일 수가, 오른쪽 위 Directory Structure에는 폴더 트리가 있어요. 아래 Files Content에는 모든 파일 내용이 이어 붙어 있어요. 파일 사이마다 FILE: style.css 같은 줄이 끼어 있어서 어디서 파일이 바뀌는지 알 수 있어요.

마지막으로 Copy all 버튼을 눌러 전체를 복사하고 Claude 채팅창에 붙여요. 영상은 입력칸에 '이 저장소 구조 설명해줘'라고 적는 장면까지 보여 줘요. 파일을 하나씩 열어 복사할 필요 없이, 한 번 붙여 넣는 것으로 AI가 저장소 전체를 보고 답할 수 있어요.

두 꿀팁을 나란히 놓으면 이래요. 바꾸는 단어 하나로 결과물과 쓰임새가 갈려요.

바꾸는 단어열리는 서비스나오는 것언제 쓰나요
hub → diagramGitDiagram파일 사이 관계를 그린 구조도코드가 어떻게 돌아가는지 눈으로 먼저 보고 싶을 때
hub → ingestGitingest요약, 폴더 트리, 전체 코드를 묶은 텍스트저장소를 통째로 AI에 넣고 물어보고 싶을 때
영상에 없는 보충 설명

Gitingest도 오픈소스 서비스이고, 결과 페이지에 텍스트의 토큰 수를 함께 보여 줘요. 저장소가 크면 AI의 컨텍스트 창을 넘칠 수 있으니 붙이기 전에 한 번 확인해 보는 게 좋아요. 브라우저 대신 터미널에서도 쓸 수 있어요. pipx install gitingest로 설치하고 gitingest <저장소 주소>를 실행하면 digest.txt 파일이 생겨요. 하위 폴더 주소를 넣으면 그 폴더만 묶어요.

pipx install gitingest
gitingest https://github.com/coderamp-labs/gitingest
# 비공개 저장소는 GitHub 토큰을 함께 넘겨요
gitingest https://github.com/username/private-repo --token github_pat_...

비공개 저장소에 토큰을 쓰면 그 코드를 외부 서비스가 읽게 돼요. 회사 코드라면 사내 규정부터 확인해 보는 게 좋아요.

진입점Entry point
프로그램이 실행될 때 가장 먼저 읽히는 파일이에요. 웹 페이지에서는 보통 HTML 파일이 다른 스크립트와 스타일을 불러와요. 코드 읽기를 여기서 시작하면 흐름을 따라가기 쉬워요.
컨텍스트Context
AI가 답하기 전에 참고하도록 함께 넣어 주는 자료예요. 저장소 텍스트를 붙이면 AI가 그 코드를 근거로 답해요.
컨텍스트 창Context window
AI 모델이 한 번의 대화에서 읽고 기억할 수 있는 최대 분량이에요. 넘치면 앞부분이 잘리거나 아예 입력이 거절돼요.
토큰 수Token count
AI 모델이 글을 잘라 읽는 단위가 토큰이에요. 한 번에 넣을 수 있는 양과 비용이 토큰 수로 정해져서, 큰 저장소를 붙이기 전에 확인할 만해요.
