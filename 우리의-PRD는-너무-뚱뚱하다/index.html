핵심만 먼저

  1. PRD(Product Requirements Document) 하나에 비전·고객·기능·화면을 다 담으면 집중력이 떨어져요.
  2. 비전 문서는 팀이 프로젝트 내내 같은 목표를 보게 하는 문서라서, 구체적인 구현 방식은 담지 않아요.
  3. 기능 목록과 화면은 구현 방식이라 빠져야 해요.
  4. 목표 칸에도 목표만 적어요. 비용을 어떻게 맞출지(인프라, 협력업체)까지 쓰면 문서가 비대해져요.
  5. 바이브코딩으로 만드는 마크다운 문서도 명료해야 AI(Artificial Intelligence)가 잘 따라요.

PRD에 다 담으면 생기는 일

문서화에서 많이 하는 실수가 있어요. PRD라는 문서 하나에 비전, 고객, 만들 기능, 화면을 전부 담는 거예요. 아래 화면에서 PRD 밑에 손글씨로 적힌 네 단어가 바로 그 네 가지예요. 이렇게 한 문서에 많이 모이면 읽는 사람의 집중력이 떨어져요.

비전 문서는 무엇을 하는 문서일까요

발표자는 비전 문서의 정의로 돌아가요. 화면 위쪽 흰 상자에 적힌 정의는 '팀원들을 프로젝트 기간 동안 같은 목표에 집중하게 만드는 문서'예요. 그 아래 세 줄이 담을 것과 담지 않을 것을 나눠요. 진짜 비전만 담고, 구체적인 구현 방식은 담지 않고, 방향성·목적·철학을 담아요. 노란 테두리를 친 줄이 이 영상의 핵심이에요.

목표만 남기고 '어떻게'는 빼요

그럼 무엇이 구현 방식일까요. 발표자는 두 가지를 꼽아요. 기능 목록과 화면이에요. 화면에서는 'PRD에서 빠질 것' 아래 두 항목에 줄을 그어 지워요.

목표 칸에 '어떻게'가 섞이는 실수

더 자주 하는 실수는 목표 항목 안에서 생겨요. 발표자가 든 예시는 휴대용 기기 팜파일럿(Palm Pilot) 개발팀의 목표 네 가지예요. 화면 글씨가 작아서 아래 표로 옮겼어요.

항목화면에 적힌 목표
크기셔츠 주머니에 들어간다. 주머니가 보기 흉하지 않을 만큼 가벼워야 한다
비용고급 종이 다이어리보다 싸다 ($300)
단순성종이만큼 단순해야 한다. 곧바로 켜지고 사용법이 쉬워야 한다
PC(Personal Computer)와 동기성고객과의 주요 접촉 도구로 PC를 사용한다

아래 화면에서 노란 줄을 친 게 비용 항목이에요. 여기엔 '종이 다이어리보다 싸다'는 목표만 있으면 돼요. 그 밑의 손글씨처럼 이 비용을 '어떻게' 맞출지, 인프라나 협력업체 목록까지 적으면 문서가 비대해져요. 그러면 목적 문서를 한눈에 이해하기 어려워져요.

영상이 말한 내용을 한 장으로 정리하면 이래요. 왼쪽 비전 문서에는 목표만 남고, '어떻게'에 해당하는 것은 오른쪽으로 빠져요.

영상에 없는 보충 설명

팜파일럿은 실제로 이 목표에 가깝게 나왔어요. 컴퓨터 역사 박물관은 셔츠 주머니에 들어가는 크기, 버튼 하나로 하는 PC 동기화, 빠른 반응, 299달러라는 가격을 성공 요인으로 꼽아요. 개발자 제프 호킨스는 나무로 깎은 모형에 젓가락을 스타일러스 삼아 디자인을 시험했어요. 목표가 짧고 분명했기에 이런 식으로 확인할 수 있었던 셈이에요.

AI에게 주는 문서도 똑같아요

발표자는 마지막에 바이브코딩으로 넘어가요. 마크다운 문서를 AI에게 줄 때도 문서를 명료하게 만들어야 AI가 보고 잘 따라요. 아래 화면 왼쪽에 팜파일럿 목표 원문이 있고, 맨 아래 줄은 '단순하고 명료한 목표다. 단순하다고 해서 난이도가 낮은 건 아니다'예요.

영상에 없는 보충 설명

Claude Code 공식 문서도 같은 얘기를 해요. 지시가 구체적이고 간결할수록 Claude가 더 꾸준히 따르고, CLAUDE.md 한 파일은 200줄 아래를 목표로 하라고 해요. 길어지면 컨텍스트를 더 먹고 지시를 따르는 정도가 떨어진대요. 일부 코드에만 필요한 지시는 해당 파일을 다룰 때만 읽히는 규칙 파일로 나누라고 권해요.
